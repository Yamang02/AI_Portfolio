# Backlog 작성 규칙

실행 단위로 승격하지 않은 문제와 잔여 신호는 [docs/backlog.md](../backlog.md)에 기록한다.

## 작성 기준

- 아직 Brief·Epic으로 계획할 만큼 충분히 정해지지 않은 **문제와 근거**만 남긴다.
- 항목마다 현재 문제, 발견 맥락, 후속 판단에 필요한 관찰 가능한 신호를 간결하게 적는다.
- 독립 실행 범위가 확정되면 [Brief](../workflow/briefs/README.md) 또는 [Epic](../epic/README.md)이 작업을 소유한다.
- 이미 승격되어 실행 소유자가 존재하는 항목은 중복 추적하지 않는다. 확인 후 활성 백로그에서 제거한다.
- 백로그 README에는 수동 상태 목록이나 완료/아카이브 내역을 만들지 않는다.
- 과거 `archive/`의 내용은 명시적 조사·복구 요청이 없다면 찾아보지 않는다. 자동 아카이빙 정책은 없다.
