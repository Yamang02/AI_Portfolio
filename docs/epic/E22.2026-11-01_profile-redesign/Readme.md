# Epic E22: profile-redesign

## 목표

- `profile`이 React + Tailwind v4 + Motion 기반의 독립 프로젝트(pnpm, 최신 의존성)로 동작하고, 빌드 결과물에 본문 HTML이 프리렌더되어 SEO가 현재 수준 이상으로 유지된다.
- 페이지가 "명함" 컨셉으로 재구성된다. 오프닝(앞면) → 소개 → 이력 → 연결(뒷면) 네 구간을 스크롤만으로 1분 안에 훑을 수 있고, 핵심 정보(누구·무엇·이력·연락처)가 고르기나 모달 뒤에 숨지 않는다.
- 오프닝에서 〈타락천사〉가 찢겨 걷히며 hero.jpg가 드러나는 연출이 페이지에서 가장 강한 장면으로 인상과 웹 기술을 보여준다. 나머지 구간은 세이지 그린 + 세리프 톤의 에디토리얼을 기본으로 하되, 구간마다 내용 이해를 돕는 고유한 연출을 하나씩 가질 수 있다.
- 모바일에서도 같은 구성이 읽기 편하게 동작하고, `prefers-reduced-motion` 사용자에게는 정적·축소 연출이 제공되며, 모바일 LCP 2.5초 이하를 유지한다.

## 배경 / 맥락

### 현재 상태

- `profile/index.html` 단일 파일(약 750줄)에 마크업, 인라인 스크립트 4개, Tailwind Play CDN 설정이 모두 들어 있다. 카드·모달은 템플릿 문자열 + `innerHTML`로 렌더링한다.
- `package.json`에 React 19 / Vite 6이 선언되어 있으나 `src/`가 없어 사용되지 않는다(E15 P01에서 연결되지 않은 `profile/src/`를 dead code로 제거).
- `public/content.json`은 E13에서 실제 콘텐츠로 채웠지만 어디에서도 읽지 않으며, 루트 `.gitignore`의 `profile/public/*` 규칙 때문에 git에 추적되지 않는다. 콘텐츠는 HTML과 JS 배열에 하드코딩되어 있다.
- 모션은 역할 문구 keyframe, 로고 텍스트 순환, hover 확대 정도이며 스크롤 진입·모달 전환 연출이 없다.
- 배포는 GitHub Actions(Node 18, `npm ci`) → S3 + CloudFront이며, EmailJS 키는 Vite HTML `%VITE_*%` 치환으로 주입된다.

### 문제

- Play CDN은 런타임 JIT로 동작해 운영 환경에 부적합하고, `md:col-span-${n}` 같은 동적 클래스가 빌드 방식 전환 시 깨지는 구조다.
- 단일 HTML + `innerHTML` 구조로는 레이아웃 재구성과 상태 기반 모션(진입/퇴장, 공유 레이아웃 전환)을 유지보수 가능한 형태로 구현하기 어렵다.
- 카드가 거의 동일한 형태로 반복되어 템플릿 인상이 강하고, 모바일 내비게이션 부재·모달 고정 높이 등 사용성 결함이 있다.

## 특이점

- **profile은 frontend와 독립 관리**: 소규모 단일 페이지이므로 frontend(Tailwind 3.4, npm)와 버전을 맞추지 않고 최신 버전(React 19.3, Vite 8, TypeScript 7, Tailwind 4.3, Motion 14)과 pnpm으로 관리한다. CI Node는 22로 올린다(Vite 8 요구 `^20.19 || >=22.12`, Node 18 EOL).
- **빌드 시 프리렌더**: 현재 정적 HTML에 본문이 포함되어 크롤러(특히 네이버)가 읽을 수 있다. CSR로 바꾸면 이 성질을 잃으므로, 빌드 후 `react-dom/server`로 렌더한 HTML을 `dist/index.html`에 주입하고 클라이언트는 `hydrateRoot`로 연결한다. 별도 SSG 프레임워크는 도입하지 않는다(단일 라우트라 과함).
- **P01은 동작 보존 리팩터**: 화면·문구·인터랙션을 바꾸지 않는다. As-Is 분석에서 확인된 시각 결함(역할 순환 오프셋, `rounded-DEFAULT` 미생성, 모달 고정 높이, 모바일 nav 부재)은 레이아웃 재구성 Phase에서 함께 처리한다.
- **콘텐츠 단일 소스**: `content.json`을 `src/content/`로 옮겨 정적 import한다. 런타임 fetch를 쓰지 않아 로딩 상태가 없고 프리렌더와 타입 검사가 가능하다. 타입은 E13에서 설계한 discriminated union(`modalLayout` 기준)을 기반으로 한다.
- **컨셉은 "명함"**: 방문자가 10~30초 안에 누구인지, 무엇을 하는지, 믿을 만한지, 어떻게 연락하는지를 알게 하는 것이 목표다. 두 원칙을 따른다.
  - 핵심 정보는 숨기지 않는다. 고르기·탭·모달 뒤에 두지 않고 스크롤만으로 모두 보이게 한다.
  - 심플함은 정보를 숨겨서가 아니라 줄여서 만든다. 항목마다 한 줄로 압축하고, 깊은 내용은 이 페이지에 담지 않고 바깥으로 연결한다.
- **사이트 간 역할 분담**: 이 페이지는 첫인상·요약·연결만 맡는다. 상세 기록은 portfolio.yamang02.com, 사업은 yamangsolution.com, 결과물은 skkuartclub.kr·design.yamang02.com이 맡는다.
- **페이지 구성 (명함의 앞면과 뒷면)**:

  | 구간 | 역할 | 내용 | 방식 |
  |------|------|------|------|
  | ① 오프닝 (앞면) | 인상, 기술력 | 정사각형 〈타락천사〉가 hero 흰 틈을 따라 가로로 찢겨 위→오른쪽, 아래→왼쪽, 눈→오른쪽으로 말리며 사라진 뒤 hero.jpg가 드러나고 상단 `YAMANG`이 먼저, 하단 `LEE JEONGJUN`이 짧은 간격 뒤에 표시됨 | 페이지 로드 시 자동 재생 1회 ([P02](./P02.torn-opening-scene.md)) |
  | ② 소개 | 누구, 무엇 | 섹션 머리에 역할 탭 + 재생/일시정지, 왼쪽 "Hello! I'm {역할} 이정준" + 짧은 사실 한 줄, 오른쪽 역할 사진 2×2(사분면 고정, 교차점이 움직여 활성 사진이 원본 비율로 가장 크게). 3초 자동 순환 | 정적 에디토리얼 + 순환 ([P03](./P03.intro-role-grid.md)) |
  | ③ 이력 | 믿을 만한가 | 나무형 연표. 연도 단계마다 카드 최대 4개(경력·교육·산출물 모두 이미지 중심의 같은 카드). 줄기 노드는 시간순(최신이 위), 카드는 좌우 교차. 종류는 선·노드로만 구분(경력 굵은 실선, 교육 대시선 + 빈 노드, 산출물 얇은 실선) | 폭·높이에 카드가 들어오면 고정 화면 + 연도 슬롯 스크러빙(연도 5단계·목차·방향 인식 스냅), 가독 크기를 지킬 수 없으면 일반 스크롤 ([P04](./P04.history-tree.md)) |
  | ④ 연결 (뒷면) | 개인 채널 연결 | `연결`과 야망솔루션 홈페이지·포트폴리오·이메일·Threads 링크 | 제목이 먼저 등장하고 섹션이 절반 노출된 뒤 0.5초 텀을 두어 표면색에서 영상으로 페이드인; 영상 가장자리 blur와 상단 흰 그라데이션으로 경계를 부드럽게 연결; 원형 CTA 네 개를 하늘 영역에 배치 |

- **모션 원칙**: 가장 강한 연출(화면 전체를 쓰는 장면)은 오프닝이 가진다. ②~④는 구간마다 내용 이해를 돕는 주 연출을 하나씩 둘 수 있다(예: ② 역할 순환, ③ 고정 화면 + 연도 슬롯 스크러빙). 스크롤 연동 변형은 허용한다. 화면 고정(sticky)은 오프닝과 ③ 이력에만 쓰며, 이력에서는 장면 연출이 아니라 연도 탐색 장치로 쓴다. 스크롤 가로채기(JS 휠 차단)는 어디에도 쓰지 않는다. 스냅은 스크롤이 멈춘 뒤 정렬만 하고, 구간을 빠져나가는 방향의 스크롤은 붙잡지 않는다. 모든 연출은 `prefers-reduced-motion`에서 최종 상태로 대체한다. 모션 배경 섹션은 최대 하나만 둔다.
- **〈타락천사〉는 야망솔루션의 메인 테마 비주얼**이다. hero.jpg와 구도(팔·휴대폰 너머로 노려보는 눈)가 닮은 점을 오프닝의 눈 전환에 쓴다. yamangsolution.com을 만들 때도 같은 그림과 처리를 써서 profile에서 넘어갈 때 이어지게 한다. 카바넬(1889년 사망) 작품이라 퍼블릭 도메인이다.
- **띠 분할**은 hero.jpg의 가로 띠 3개 + 흰 틈 구성이며 오프닝의 시각 문법이다. 띠로 자르기 전 원본이 없으므로 hero.jpg에서 띠를 잘라 쓴다(띠 개수 3개 고정).
- **제거 대상**: 현재 관심사 섹션, 정체성 카드 4개(② 소개가 대신함), 주요 활동 벤토 그리드와 활동 모달 3종(③ 이력과 바깥 링크가 대신함), 명화 장면(오프닝의 〈타락천사〉만 남김), 직접 그린 작품.
- **원본 자산은 루트 `asset/`**(gitignore 처리)에 둔다. `asset/opening/`은 오프닝, `asset/intro/`는 역할 사진, `asset/history/`는 이력 가지 썸네일·영상, `asset/connect/`는 연결 구간 배경 영상, `asset/archive/`는 쓰지 않는 원본이다. git에는 스크립트로 변환한 웹용 결과물만 `profile/src/assets/`에 커밋한다(파일명 해시로 S3 장기 캐시 문제 회피). 연결 배경 결과물은 `profile`의 `assets:connect` 명령으로 생성한다.
