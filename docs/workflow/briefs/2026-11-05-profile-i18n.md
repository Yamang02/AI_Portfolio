> Status: draft
> Owner: profile

## 문제와 목표
- 현재 문제: `profile`은 한국어 단일 언어다. 문구는 `content.json`에 모여 있으나 로케일 개념이 없고, 일부 문구(`aria-label`, `Website ↗`, `Portfolio ↗`)와 `index.html` 메타가 하드코딩돼 있다.
- 기대 결과: 한국어(`/`)와 영어(`/en/`)가 각각 프리렌더된 정적 HTML로 제공되고, 상단 `KO | EN` 토글로 이동할 수 있다.
- 범위: 로케일별 콘텐츠 분리, 하드코딩 문구 이관, 로케일별 프리렌더(`dist/index.html`, `dist/en/index.html`), 로케일별 `<html lang>`·메타·`hreflang`, 언어 토글, 영문 문구 초안.
- 제외 범위: 3개 이상 언어, 브라우저 언어 기반 자동 리다이렉트, localStorage 언어 저장, i18n 라이브러리 도입, `profile` 외 앱.

## 설계
- URL: 한국어 `/`(기존 유지), 영어 `/en/`. 언어는 URL로만 결정하며 자동 리다이렉트와 저장은 하지 않는다.
- 콘텐츠: `content.json`을 `content.ko.json`·`content.en.json`으로 분리하고 `ProfileContent`를 공통 계약으로 쓴다. 날짜 표기와 `presentLabel`도 로케일별로 둔다. 하드코딩 문구는 JSON으로 옮긴다.
- 라이브러리 없이 `getProfileContent(locale)`와 `App`의 `locale` prop(또는 Context)로 내려준다. 서버·클라이언트 모두 같은 경로의 같은 로케일로 렌더해 hydration 불일치를 막는다.
- 빌드: `vite build` 1회. 프리렌더에서 템플릿의 `lang`, title, description, og/twitter, `og:locale`, canonical, `hreflang`을 로케일별로 치환한다. `index.html`의 한국어 메타는 치환 자리표시자로 바꾼다.
- 영문 문구: 직역이 아닌 영어권 독자 기준으로 다듬는다(예: 성미회는 설명을 풀어 쓴다). 작품 크레딧은 영어 표기로 바꾼다. 초안은 작성 후 사용자가 검수한다.
- 위험: 영어 문구가 길어져 내비게이션·역할 탭 레이아웃이 깨질 수 있다.
