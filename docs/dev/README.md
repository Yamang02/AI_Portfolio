# Development documentation

Own durable technical responsibility, boundary, architecture, contracts, conventions, and verification guidance.

## Reading route
1. Relevant [Product](../product/README.md) meaning or approved workflow design.
2. Existing [technical docs](../technical/README.md) when still authoritative.
3. Actual backend, frontend, profile, infrastructure, and configuration code.
4. [Cross-stack conventions](./conventions.md) for shared coding rules.
5. [Development commands](./development.md).

## Transition rule
Until ownership-by-subject migration is completed, `docs/technical/` and `docs/basis/quality/` are maintained legacy references. Do not automatically replace them with an empty new document or assume a copied ClipTagger architectural rule applies.

## Writing
Describe owner and invariant first; specify contracts and representations next, code paths and verification only where useful.
